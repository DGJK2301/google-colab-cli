# v0.7.0rc3: Operational Recovery v1

This release candidate adds three independent but composable surfaces:

```text
doctor → local readiness evidence
attach → assignment recovery
monitor → durable local run evidence
```

It does not add high-memory allocation, capacity retry, compute-unit
inference, notebook-run unification, MCP, XoFTR recipes, or Drive data
governance.

## New commands

```bash
colab doctor [--json] [--network]
colab attach --endpoint ENDPOINT -s NAME [--json]
colab monitor JOB -s NAME --output DIR [--json]
```

Stable schemas:

```text
colab.doctor.v1
colab.attach.v1
colab.monitor.state.v1
colab.monitor.summary.v1
```

`monitor` preserves raw stdout/stderr, periodic job state and resources,
event evidence, resumable offsets, and a final summary. Terminal exit codes
are propagated only after all currently reported log bytes are copied.

`attach` adopts only an exact current-account endpoint. It establishes a
control kernel and keep-alive by default; local failure never releases the
remote assignment.

`doctor` is local-only by default and never serializes credential values.
`--network` is a separate bounded assignment query.

## Review closure and local acceptance

The integration review additionally closed four lifecycle gaps:

- attach claims a local name and endpoint atomically, and rollback removes only
  the claim that still owns that endpoint;
- detached keep-alive receives the selected OAuth client configuration;
- Windows token-cache permission checks recognize stable broad-principal SIDs;
- one-shot monitor state records a snapshot instead of a running lifecycle.
