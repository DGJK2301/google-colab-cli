# v0.7.0-rc1: Structured Observability v1

## Scope

This release candidate adds a machine-readable, read-only observation surface
on top of the existing session and reconnectable-job control plane. It does not
add machine allocation, high-memory shape selection, compute-unit queries,
monitor daemons, MCP, framework-specific recipes, or Drive mirroring.

## Commands

```bash
colab sessions --json
colab status -s NAME --json
colab status -s NAME --probe --json --timeout 20
colab jobs -s NAME --json
```

Schemas are versioned as:

```text
colab.sessions.v1
colab.status.v1
colab.jobs.v1
```

## Observation model

The JSON contracts keep three layers distinct:

```text
local requested state
server assignment state
runtime-observed resources
```

The command does not claim that a requested accelerator is the physical GPU
model. Mismatches are emitted as structured warnings.

## Probe safety

Probe mode requires an explicit session and one finite positive total timeout.
It performs:

```text
existing runtime resource API
→ optional exact existing-kernel supplemental request
→ field-level merge
```

It does not:

```text
assign
create a kernel
restart
release
mount Drive
install packages
submit a job
```

When no kernel ID is recorded, the resource endpoint can still produce RAM,
disk, and GPU information; driver, temperature, and boot identity remain
unavailable. Timeouts and source failures produce partial structured results
rather than an unhandled traceback.

## JSON stream contract

Machine mode reserves stdout for exactly one JSON document. Authentication and
dependency diagnostics are redirected to stderr. Tokens, credentials, auth
headers, and secret environment values are excluded from the schemas.

Compute-unit balance and consumption rate remain `null` with
`not_queried_by_structured_observability_v1`. They are not inferred from the
browser UI or a hard-coded price table.

## Job observations

`jobs --json` reuses the existing persisted job runtime and adds:

```text
state
heartbeat_at
returncode
error
stdout path/size
stderr path/size
runtime identity
runner liveness
```

Human-readable command output remains compatible with v0.6.0.post1.

## Authentication lifetime

The bundled Cloud SDK OAuth client now requests `accounts.reauth` and enables
google-auth's RAPT refresh path. Normal one-hour access-token expiry is handled
silently by the cached refresh token. If Google requires a password,
security-key, or organization reauthentication challenge, it must be completed
in an interactive local terminal; the returned RAPT token is cached for later
refreshes. Account or organization session policy can still require a future
human reauthentication.

This does not import credentials from the official Colab VS Code extension.
That extension uses its own OAuth client and VS Code `SecretStorage`; this CLI
continues to own only `~/.config/colab-cli/token.json`.
