# v0.7.0rc2: Transfer Lifecycle v1

## Scope

This release candidate closes the local transfer lifecycle around the
existing verified chunk algorithm. It does not add a monitor daemon,
doctor, notebook execution unification, resource allocation policy, MCP,
or model-specific behavior.

## Commands

```bash
colab upload -s NAME --resume --json LOCAL REMOTE
colab download -s NAME --resume --json REMOTE LOCAL
```

Human output remains compatible. JSON uses `colab.transfer.v1`.

## Single-writer ownership

A local `TransferLease` is acquired before partial inspection and before any
remote connection. Upload leases bind the assignment endpoint and normalized
remote destination, regardless of which control-plane auth mode selected the
same recorded runtime. Download leases bind a platform-normalized local
destination while preserving its path spelling in resume evidence.

The second writer fails immediately. Stale metadata is recycled only when
PID plus process-start identity proves the previous owner has exited or the
PID has been reused. Unknown identity is not treated as stale.

## HTTP lifecycle

`ContentsClient` owns one reusable `requests.Session`. Chunks share its
connection pool, while every request retains explicit connect/read timeout
tuples. Responses are closed, the Session is closed before the remote
executor, and close failures remain warnings.

## Interruption

Ctrl+C returns 130. A verified deterministic partial remains available for
the emitted resume command. History records `state=interrupted`; cleanup
exceptions cannot replace the interruption result.

## JSON result

The final document includes:

```text
completed_bytes
total_bytes
resumed_from
elapsed_seconds
mib_per_second
eta_seconds
retry_count
sha256
partial_path
lease evidence
resume argv/command
warnings and structured error
```

Progress is stderr-only. Runtime tokens and credentials are redacted.

`retry_count` includes actual HTTP chunk replays and idempotent
control-channel reconnects. A lost response that is reconciled at the
already-committed byte boundary is not counted as a replay.

## Verification boundary

Unit and contract tests cover connection reuse, response close, concurrent
writer exclusion, process-identity stale recovery, ambiguous response
reconciliation, interruption/resume SHA equality, cleanup precedence, and
JSON purity.

The live free-CPU script accepts 8 MiB or 64 MiB fixtures and chunk sizes
0.25/0.5/1/2 MiB. Live Colab execution remains a release-signing gate, not
a unit-test claim.
